## Реализованная основа

`app/structure-core/types.ts` задаёт BlockState, Cell, ConnectionPort, ModuleDefinition, ModuleInstance, GeometryGenerator и StructureProject. `index.ts` реализует строгий разбор формата 1, Stone Room, повороты/перенос, сериализацию и отчёт о пересечениях. Библиотекой могут пользоваться браузер, сервер и будущий MCP без зависимостей от React, Three.js, Node API или модели ИИ.

Это ограниченное подмножество будущей схемы: только генератор `room.stone_basic.v1`, плоские экземпляры. ElementDefinition, вложенные модули, ссылки на палитры и сохранённые соединения будут добавлены с миграцией формата, когда появится их исполнитель. Не записываем в проект неработающие сущности и исполняемый JavaScript от клиента. Произвольная геометрия позже будет представлена декларативными ячейками/операциями, с теми же лимитами и проверками.

## Следующие проверяемые шаги

1. UI (реализовано в этапе 2, см. ниже): `app/structures/page.tsx`, `app/components/structures/StructureStudio.tsx` и `StructurePreview.tsx`. Панель меняет только параметры экземпляра. Пустой проект допустим; добавление комнаты создаёт стабильный ID один раз. Переиспользовать `app/components/editor/EditorSection.tsx` и `PreviewLoading.tsx`, если подходит UI. Для блоков собирать видимые грани секциями 16³, группировать по материалам, отдельно обрабатывать прозрачные поверхности. При изменении комнаты инвалидировать её старые/новые секции и соседние секции. Никакого Mesh на каждый блок. Начать с кубов; slabs/stairs/fences требуют отдельного адаптера blockstate→geometry, не выдавать кубы за точную модель сложных блоков.
2. Камера (реализовано в этапе 2): OrbitControls для обзора, PointerLockControls из уже установленного Three.js для свободного полёта. WASD в горизонтальной плоскости, Space/Shift по Y, скорость в блоках/секунду; движение по delta time, сброс клавиш при blur/смене режима, Escape освобождает мышь. Проверить проход через стены и осмотр изнутри без коллизий.
3. Хранение: `app/server/structure-projects.ts` поверх getSql; таблица с `id`, `user_id`, `revision`, `format_version`, `document jsonb`, `updated_at`. Route handlers `app/api/structures/route.ts` и `[id]/route.ts` вызывают общий сервис. Запись атомарным UPDATE с `WHERE id=… AND user_id=… AND revision=expectedRevision`, увеличение revision в том же запросе, HTTP 409 при конфликте. Batch применяет изменения к копии, валидирует и записывает один документ; ошибка не меняет исходный проект. Сохранение JSON в ядре этой итерации ещё не означает серверное хранение.
4. Экспорт: серверный адаптер `.schem` поверх сгенерированных ячеек, отдельные проверки NBT/палитры/индексов/границ/смещения и gzip. Перед реализацией сверить актуальную спецификацию Sponge Schematic и поддержку WorldEdit. Выбрать явную Minecraft/DataVersion: текущий каталог персонажей 26.1.2 не является основанием экспортировать проект как 1.21.5. `air` очищает, `void` не меняет мир; разреженные пропуски нельзя автоматически превращать в air. Обязательна ручная вставка Stone Room в реальный Minecraft+WorldEdit: автоматический разбор файла её не заменяет.
5. MCP: локальный stdio-адаптер предпочтителен для desktop/CLI, не требует входящего порта. Тонкий клиент общего API: сначала get_project, update_instance, validate_structure, затем batch и остальные инструменты. Для локального dev можно использовать локальное хранилище через тот же сервис, но не обращаться к production DB напрямую из MCP. Для удалённого приложения требуется отдельная ограниченная авторизация API: существующая Google-сессия браузера не передаётся автоматически в stdio. Предлагается выдаваемый после Google-входа отзывной токен, ограниченный Structure API, с хешем в БД и сроком жизни; это делегирование доступа текущему аккаунту, а не замена Auth.js. Детали выдачи и безопасного локального хранения проработать на этапе MCP; токены Codex и браузерные cookies не копировать. Настройку официального Codex-клиента сверить по его документации в той итерации.
6. Синхронизация: для Vercel начать с короткого polling метаданных revision при активной вкладке, затем загрузки актуального документа. Это проще отдельного постоянного WebSocket-сервера. При несохранённых правках показывать конфликт, не заменять их молча. Условная запись по revision обязательна независимо от транспорта. SSE рассматривать после проверки ограничений хостинга и необходимости более низкой задержки.
7. Только после сценария браузер→сохранение→экспорт→WorldEdit и Codex→MCP→браузер добавлять библиотеку элементов, вложенность и соединение модулей. Замки и миры не входят в текущую итерацию.

В этапе 2 обновлены пользовательская/техническая документация и публичный блок новостей; создан Vercel preview по AGENTS.md. Новых зависимостей нет.

## Этап 2: реализовано 1 ноября 2026

Добавлены `/structures`, навигация "Постройки", редактор экземпляров Stone Room и ленивый Three.js viewer. Пустая сцена, стабильные UUID, настройки размеров/материалов/проёмов/позиции/поворота, несколько комнат и предупреждения пересечений работают поверх StructureProject. Объединённые видимые грани группируются по материалам в секциях 16³, инвалидируются изменённые секции и соседи. В UI только непрозрачные полные блоки с условными цветами; прозрачность и сложные blockstates отложены до отдельного адаптера. Камера: OrbitControls и свободный полёт PointerLockControls без коллизий; обработаны resize, blur, Escape, потеря WebGL и освобождение ресурсов. Сохранение, экспорт, MCP, синхронизация и библиотека остаются следующими этапами. Формат ядра не изменён.

Проверки этапа 2: 69 node:test (ядро 9, viewer 5, entity preview 17, voice 8, auth policy 4, command AI 26), интеграционный auth-session, TypeScript и production build прошли. Локально в браузере проверены пустая сцена, добавление комнаты, размеры/материалы/проёмы/позиция/поворот, отображение 3D; в Chrome — pointer lock, изменение скорости, перемещение и Escape; во встроенном браузере — сообщение об отказе pointer lock. Vercel preview создан со статусом READY. Проверка удалённого UI и мобильной раскладки не завершена: сохранённая настройка доступа browser tool блокирует preview и localhost, в том числе после текстового разрешения пользователя. Недоступный WebGL и восстановление контекста реализованы, но вручную в браузере пока не проверены.
