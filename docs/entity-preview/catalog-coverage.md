# Полный каталог конструктора: Minecraft Java 26.1.2

Проверено 16 октября 2026. Под "полным каталогом" здесь понимаются **все 94 ID сущностей и 69 различных предметов, которые сейчас предлагает `/summon`**, а не все предметы Minecraft, содержимое `/give`, все NBT-комбинации или все состояния AI.

## Что реализовано

| Область | Покрытие | Ограничение |
| --- | --- | --- |
| Геометрия | 94/94 ID обработаны; 93 имеют видимую геометрию | `area_effect_cloud` использует NoopRenderer: его изображение состоит из частиц |
| Текстуры | Все 235 непосредственно используемых PNG найдены, экспортированы и проверены | Vanilla 26.1.2; без загрузки пользовательских пакетов и сетевых скинов |
| Предметы | 69/69 ID; все 80 разрешённых пар "предмет + слот"; 3 игровых контекста на предмет | Только слоты и компоненты текущего редактора; луки/арбалеты не используются/не заряжаются |
| Надетая экипировка | 5186 вариантов игровых слоёв по сущностям, возрастам и позам | Minecraft сам определяет видимость; отсутствующий слой не заменяется нарисованной вручную бронёй |
| Внешность | 36 детских вариантов; 7 окрасов лошади; окраска кожи; 18 отделок × 11 материалов; базовые цвета и до 16 слоёв узоров щита/флага | Не добавлены отсутствующие в редакторе профессии, биомы, saddle/horse armor, markings и прочие варианты; HUMANOID_BABY не рисует trims в самой игре |
| Позы и пассажиры | 1046 статичных поз, включая арбалет разбойника; обе точки крепления (PASSENGER и VEHICLE) | Не воспроизводятся все игровые поправки посадки и позы AI |
| Анимации | Нет воспроизведения по времени | Экспортируются статичные результаты setupAnim, а не анимируемый скелет |
| Эффекты | Невидимость скрывает тело, снаряжение сохраняется | Нет glint, огня, outlines, частиц и всех shader effects |

Один факт загрузки модели не считается полной поддержкой сущности. Фаерболл, ракета и сфера опыта остаются обращёнными к камере, как их игровые renderer; элитры используют сложенную исходную позу baked-модели. Браузер использует таблицу возможностей конкретного игрового renderer/pose: например, житель показывает головные предметы и предмет в руках, но не гуманоидную броню; лошадь/разоритель не показывают содержимое обычных equipment slots. У поборника/вызывателя в спокойной позе оружие скрыто. Снаряжение и характеристики при этом остаются в команде и текстовом предпросмотре.

## Как получаются ресурсы

`Minecraft client JAR + библиотеки клиента → Java CPU exporter → JSON/PNG → Three.js`.

`CaptureScenes.java` вызывает настоящие `EntityRenderer.submit`, `Model.setupAnim`, `Model.renderToBuffer`, слои брони, голов и предметов. Collector получает quads до GPU и сохраняет UV, normals, цвет/alpha и уже применённые геометрические преобразования. Зеркальность, деформации слоёв брони и повороты деталей применяет сам Minecraft. Ручных координат мобов/предметов нет. `VanillaAssets.java` использует настоящий `ModelBakery` и codecs современных item definitions; специальные модели щитов, флагов, трезубцев, голов и элитр не заменены иконками.

Скрытый маркер в `ItemStackRenderState` проходит через настоящий слой предмета и записывает его матрицу. Модель предмета отдельно запекается в THIRD_PERSON_RIGHT_HAND, THIRD_PERSON_LEFT_HAND и GROUND. В браузере эти данные соединяются; разные сущности не получают одно универсальное крепление руки. Контентные хэши позволяют переиспользовать 981 meshes вместо дублирования геометрии всех 1046 поз и 5186 вариантов снаряжения. Окрасы/узоры переиспользуют геометрию, как в игре.

Иерархия ModelPart/pivot участвует в нативном вычислении, но формат 3 хранит результат в координатах сущности. Для будущих анимаций потребуется экспортировать иерархию/каналы дополнительно; нынешний формат не объявляется скелетным GLB. Предыдущий формат 1 с иерархией пяти семейств сохранён для исследования.

Нужны небольшие **адаптеры состояний**: инициализация registry/data components, default variants современных животных, plains/none villager data, размеры слизней, блоковые состояния TNT/рамок/грибов/тыквы, default flags стойки, окрасы лошади, арбалетная/спокойная поза разбойников и масштабы из DefaultAttributes. Полноценный `extractRenderState` требует игрового мира; текущий экспортёр задаёт поддерживаемые статичные состояния явно и затем запускает нативные модели и слои. Это существенная граница точности, а не эмуляция всей игры.

Таблица `default-textures.json` получена из `EntityModelLoader` Asset Renderer на версии 26.1.2. Исходный инструментарий исследован и реально запущен отдельно от Java image renderer на коммите `2b69cd3464080dcb633038bd8d68a85201e75268`; детали и ссылки — в [research.md](research.md). Его таблицы полезны для discovery/default textures, но текущий полный каталог получает фактические submissions непосредственно из клиента. Fabric и запущенный игровой клиент для этого экспорта не понадобились.

## Воспроизведение

Проверено на macOS arm64 с установленным vanilla-клиентом 26.1.2, библиотеками/нативными библиотеками launcher и Java 25. Сценарий проверяет SHA1 client JAR против launcher JSON; SHA256 исходного клиента: `b1b3158572666445eff01e82fad8c7de2e4953db6d354f311730d77a8359d0b0`.

```sh
python3 tools/entity-export/capture.py \
  --minecraft-dir "$HOME/Library/Application Support/minecraft" \
  --java /opt/homebrew/opt/openjdk@25/bin/java
python3 tools/entity-export/verify-catalog.py
npm run test:entity-preview
npm run build
```

`capture.py` сам пересоздаёт `catalog.json` из TypeScript-данных редактора, компилирует Java, экспортирует во временную директорию, проверяет полноту и только после успеха заменяет каталог. Предыдущие ресурсы сохраняются при ошибке. `--out` позволяет сравнить независимый повторный экспорт. JSON канонизирован, manifest содержит SHA256 ресурсов и исходников экспортёра. Java/Minecraft нужны только на машине подготовки; ни посетитель, ни Vercel их не запускают.

`verify-catalog.py` проверяет все ID, ожидаемые позы, непропущенные предметы, ссылки, отсутствие missingno, quad topology, finite vertices/matrices и хэши. Node-тесты дополнительно сверяют списки с реальным редактором и проверяют все динамические маски/палитры, команды, возраст, цвета и видимость слоёв. Добавление нового ID в редактор без повторного экспорта ломает проверку.

## Ограничения и следующий шаг

Текущий каталог поддерживает только vanilla. Старый `export.py --pack` не применяется к новому pipeline. Для обычных ресурс-паков потребуется объединённый ResourceManager с приоритетами пакетов и повторная игровая выпечка item/equipment definitions, atlas sources, метаданных и текстур. CEM/EMF/OptiFine/modded entity renderers и shader packs — отдельная интеграция. Посетитель не загружает свой ресурс-пак.

Для полного воспроизведения всех возможностей игры нужны дополнительные render-state adapters (действия, специальные имена, состояния, варианты), игровые смещения посадки, skin resolver, animation/rig export и эффекты. Получение геометрии нового моба при этом остаётся автоматическим. Проверка через настоящий CPU-код клиента сильнее ручной аппроксимации моделей, но **сравнение кадров с запущенным Minecraft пока не выполнено**, а освещение Three.js не обещается идентичным игровому.

Для MCP/source-upload deployment используется сжатый пакет из `bundle-catalog.py`; `restore-bundle.mjs` распаковывает и проверяет его при npm prebuild. Обычный Git deploy берёт те же JSON/PNG напрямую из public. Транспорт проверен отдельным roundtrip: восстановленные файлы совпадают с исходными.

Отчёт о воспроизводимости, Vercel deployment и браузерных проверках: [catalog-verification.md](catalog-verification.md).
